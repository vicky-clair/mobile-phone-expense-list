# 費用統計リスト · 费用统计清单

[English（メイン）](README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md)

Kotlin と Jetpack Compose で開発した Android 向け支出管理アプリです。ローカル台帳、支払い通知の解析、日次 CSV メール、端末の画面ロック認証を備えています。

現在は **0.3.1 開発版**で、Android 13 以降が必要です。特定メーカーにインストールを制限していませんが、実機互換性の検証は未完了です。インストール名とアプリ内表示は中国語です。README の翻訳は、アプリの日本語対応を意味しません。

## 主な機能

- 手入力、分類、検索、確認、非表示と取り消し、修正履歴、CSV 出力、データ削除。金額は整数の分単位で保持します。
- 選択したアプリの通知のみ収集し、完全に同じ通知の重複登録を防止。曖昧なものは確認対象にします。
- 画面ロックのパスワード、PIN、パターンによる解除。指紋認証は使用しません。画面がロックされてもバックグラウンド処理は継続できます。
- ウィンドウ幅に応じた単一列または一覧・詳細の二列表示。
- 通知の全体スイッチと、記帳成功・確認待ち・操作結果ポップアップの個別スイッチ。無効化時に該当する既存通知も取り消します。
- 北京時間で一日ごとの CSV を作成し、個人 SMTP アカウントで送信。サーバー受理後に端末内のレポートだけを削除します。
- WeChat、Alipay、銀行シミュレーターの支払い・入金・返金・取引以外の通知を確認する 12 項目のテスト。通知テストとテストメール送信も利用できます。

## 現在の制限

WeChat と Alipay は合成サンプルによる実験ルールです。解析できた取引も手動確認が必要です。銀行シミュレーターは通常の収集から分離されており、実際の銀行通知への対応を保証しません。支払いテストは決済を行わず、台帳にも記録しません。

スリープ、電源オフ、強制停止、通信状態によって日次処理が遅れる場合があります。SMTP サーバーの受理は受信トレイへの配達保証ではありません。送信開始後に中断された場合は「結果不明」とし、メールボックスを確認してから再送を選択します。

SMTP 設定は Android Keystore の鍵で暗号化しますが、台帳と送信待ち CSV 自体は暗号化していません。アプリのロックは画面の保護であり、データベース暗号化ではありません。システムバックアップと端末間転送は無効です。

## ビルドとインストール

JDK 17、Android SDK API 37、Build Tools 36.1.0 が必要です。Gradle 9.3.1、AGP 9.1.1、Compose Kotlin プラグイン 2.2.10、KSP 2.3.9 を固定しています。minSdk は 33、targetSdk は 36 です。

`ANDROID_HOME`、またはローカルの `local.properties` に `sdk.dir` を設定します。Windows のプロジェクトディレクトリで実行してください。

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --console=plain
```

APK は `app/build/outputs/apk/debug/app-debug.apk` に生成されます。端末のファイルマネージャーでインストールするか、デバッグを許可した端末に次を実行します。

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

更新時はパッケージ ID `cn.foldledger` と署名鍵を維持してください。リリース署名は設定していません。API 36 で一時的にコンパイルする場合は `-Pledger.compileSdk=36` を追加できますが、実機検証の代わりにはなりません。

## 初期設定

1. 端末に画面ロックのパスワード、PIN、またはパターンを設定し、その認証情報でアプリを開きます。
2. 「设置」で収集元を選び、収集を有効にしてから Android の「通知へのアクセス」を許可します。初期状態では収集は無効です。
3. 解析結果を確認・修正します。取得できない取引は手入力してください。
4. 「提醒」で全体と個別の通知スイッチを設定します。通知を無効にしても収集や日次メールは停止しません。メールには別のスイッチがあります。認証、削除確認、画面上で確認する結果は残ります。
5. 「支付与收款测试」で収集元とシナリオを選び、金額変更後にサンプルを読み込みます。匿名化した本文で個別テスト、または 12 項目の一括テストを実行できます。通知テストも設定とシステム権限に従います。
6. 「每日费用日志与邮箱设置」で再認証し、SMTP ホスト、ポート、アカウント、認証コード、送信元、宛先を保存します。まずテストメールを確認してから日次メールを有効にしてください。実際の認証コードをソース、チャット、ログに記載しないでください。

## 日次メールの仕様

タイムゾーンは `Asia/Shanghai` 固定です。当日 00:00 を含み、翌日 00:00 を含まない区間を扱います。有効にした当日から集計し、最初のレポートは翌日に生成します。毎日、北京時間 01:30 に処理を予定します。起動や再試行、手動チェックでも前日分をそれより早く送信しません。遅延分は後から処理し、明示的なテストメールはすぐに送信できます。

CSV は確定済み集計と明細を含み、未確認の取引を区別します。振替・返済を支出に含めず、非表示にした取引は日報に含めません。生成済みレポートは変更しないスナップショットです。後日の台帳修正による自動再送は行いません。

暗黙的 TLS と STARTTLS に対応し、サーバー証明書を検証します。アカウントと認証コードによるログインが必要で、OAuth のみを許可するアカウントには対応していません。

受理後に削除するのは**端末内の日報添付ファイルのみ**です。台帳と送信メタデータは保持し、メールボックス内のコピーや手動出力した CSV は削除しません。詳しくは[日次メールガイド（中国語）](docs/DAILY_MAIL.md)を参照してください。

## 開発資料

ソースは `capture`、`data`、`domain`、`report`、`security`、`ui` に分かれています。独自の Kotlin ソース、テスト、ビルド設定、XML に中国語の説明コメントがあります。生成ファイルとサードパーティーの Gradle 起動スクリプトは手動注釈の対象外です。

回帰テストは 44 件で、支払い通知を変更しないことや 01:30 のスケジュールも確認しています。ローカルテストだけでは、実際の支払い通知、端末の Keystore、SMTP 配達、メーカー固有のバックグラウンド制限は検証できません。
