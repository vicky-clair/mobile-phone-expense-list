# 运行、支付非干预与日报调度审计

审计日期：2026-09-27。目标版本：0.3.1 / versionCode 4。审计基于项目源码、构建配置、最终 APK 权限及本地自动化测试；未连接真实手机，也未操作用户支付账户或发送真实邮件。

## 结论与适用边界

在本次审计的代码中，未发现自动点击、代付、修改付款金额、读取支付密码、跳转支付链接或操作第三方支付界面的实现。支付通知路径只读取通知快照并写入本应用账本，没有调用原通知的 PendingIntent/按钮，也没有撤销或暂缓第三方通知。

这不等于保证所有手机上“百分之百正常、零影响”：系统兼容性、厂商后台策略、性能/电量、用户设置的通知行为以及真实支付通知格式仍需真机验收。当前微信/支付宝规则只匹配合成实验格式，银行仅为模拟测试，不能宣称真实自动记账已全面可用。

日报按北京时间每天 01:30 安排，统计前一日 00:00 至 24:00。应用启动、手动检查和重试均不能使昨日正式日报提前发送；更早日期的积压日报可在恢复后补发，主动测试邮件可随时发送。Android 后台任务可以延迟，不能承诺 01:30 准点送达邮箱。

## 本次发现并修复

### A-01：修改时间常量不能迁移旧任务（中等）

原版使用唯一周期名 `daily-reports` 和 KEEP。即使将 00:05 常量改成 01:30，已安装用户的旧计划仍可保留。周期执行若持续延迟，也不能确保一直对齐固定墙上时间。

修复：停用旧周期计划，按 `daily-reports-0130-日期` 安排下一次北京时间 01:30 的唯一一次性任务。Worker 在处理本次业务前等待下一天计划持久化；重复启动不会创建同日期重复任务。使用实际 WorkManager 记录检查旧任务取消、日期唯一性及目标时刻。

### A-02：零点后的补生成可能绕过目标发送时刻（中等）

原版只检查“昨日已结束”，在零点后启动应用或手动补查可生成并发送昨日文件；仅修改周期任务不足以阻止提前发送。

修复：新增 `ReportTiming.cutoff`，生成与发送均使用次日 01:30 到期边界。DAO 在取待发送批次前过滤未到期正式日报，避免旧版已生成文件提前发出，也避免未到期记录挡住用户主动测试邮件。原账本、快照格式和数据库版本保持不变。

### A-03：异步导出提示可能显示在其他应用上（低）

原版导出协程完成后可直接显示 Toast，即使用户已经切换到支付 App。它不能操作支付，但可能造成视觉干扰。

修复：实际显示前检查 Activity 处于 RESUMED 且应用会话已解锁，离开应用时取消已有操作 Toast。关闭提醒的规则仍然有效。

### A-04：异常通知内容可能使回调抛出异常（低）

通知正文来自第三方应用。原回调直接读取 Bundle，没有在读取边界处理运行时异常。

修复：提取只读快照函数；来源过滤后处理文本读取，遇到异常放弃该条，既不修改原通知，也不执行其动作。回归覆盖原通知字段/动作引用不变、未触发广播、长度限制以及白名单和组汇总过滤。

## 验证方法

- 构建调试 APK，运行全部本地回归及 Android lint，核对最终版本、签名和合并权限。
- 新增时间边界：北京时间 01:29:59 不到期、01:30:00 到期；跨年、切换手机时区、延迟后重新对齐。
- 新增邮件行为：旧附件到 01:30 才发；主动测试邮件不被等待中的日报阻塞；零点后补生成不会提前。
- 新增通知行为：快照读取不修改原通知、不触发通知动作；后台操作提示不可显示。
- 新增调度行为：旧周期任务被取消，多次注册仅保留一个同日期任务。

构建、测试数量和 APK 校验值见[验证记录](VERIFICATION.md)。通知测试使用 Robolectric，不是实际手机支付验证；SMTP 状态测试使用替身，MIME 编码使用真实库，未做真实 TLS 连接和收件测试。

## 仍需真机完成的检查

1. 开启采集后，用户自行正常完成微信/支付宝支付与收款，对比操作步骤、耗时及通知显示；应用不应跳转、遮挡或要求支付凭据。
2. 关闭提醒总开关，重复用户正常支付，确认无本应用通知或 Toast；再验证仅开启所需分类。
3. 在导出尚未完成时切换其他应用，确认不会出现导出提示。
4. 使用测试邮箱确认 SMTP 投递及附件清理，再验证 01:30 前后、断网、重启和厂商休眠策略。
5. 记录连续一天的电量、内存、卡顿及漏记情况，不用单元测试推断零耗电或完全不影响性能。

未实现主账本及待发 CSV 加密，应用锁只保护 UI；SMTP 配置使用 Keystore。未核验真实支付来源签名及多银行通知格式，真实覆盖率是本版本的主要功能限制。

WorkManager 只保证满足条件后尽力执行，系统优化可能延迟任务；当前未引入精确闹钟或全天前台服务，以避免为邮件调度增加持续干扰。[Android 官方调度说明](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)
